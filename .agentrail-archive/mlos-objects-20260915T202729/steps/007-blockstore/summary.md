mlos-virtio-blk: a read-only virtio block driver with three-descriptor chaining, feeding a Disk provider so weights come off a real device. Proof is provenance, not success: the disk image marks tiles 0xA0|(L^T) where the stub fills L^T alone, and the guest reports first byte 0xa4 for L3 T7. Read-only because weights are immutable; status primed to 0xff because 0 is Ok and an unwritten status would look like success; sectors fixed at 512 per virtio regardless of the device. Crate reshuffle: mlos-virtio is now transport+virtqueue with one crate per device (console and blk split out), and mlos-synth split into the model's definition versus mlos-lab, the one live instance -- which let both fit their budgets without inventing anything.
