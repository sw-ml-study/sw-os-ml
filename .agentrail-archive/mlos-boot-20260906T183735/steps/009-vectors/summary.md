mlos-trap-aarch64: 16-entry aarch64 vector table installed in VBAR_EL1, with a Trap capture of ESR/ELR/FAR/SPSR and all sixteen vectors named (which one fired is diagnostic on its own). Kernel reports through a plain fn behind an AtomicUsize with the console base published the same way, because a handler runs on an arbitrary stack and cannot capture anything. Proved by a deliberate read of an unmapped address: trap 4 (CurrentSpx/sync), esr 0x96000005 (ec 0x25 data abort, ISS 0b000101 level-1 translation fault), far = the address read, elr = the faulting instruction -- byte-identical on TCG and HVF. Before this, VBAR_EL1 was zero and any exception spun at 0x200, which is what made step 001's bug need a disassembler. Vector table alignment (2048) done in the linker script rather than by self-padding. Reporting only; interrupts need save/restore and are the next step.
