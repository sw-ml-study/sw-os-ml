mlos-hal + mlos-device landed, declarations only. Platform trait: 4 methods (boot_info, console, timer, irq) plus an associated PageTable type -- associated rather than dyn because mapping is on the model-fault path and cannot afford a virtual call, while device accessors are dyn because printing is not hot. mlos-hal does NOT forbid(unsafe_code) because PageTable's methods are correctly unsafe fn declarations; there are no unsafe blocks. BootInfo carries a borrowed memory-region slice (no allocator exists when it is built) with usable_bytes() as the number residency budgets are a fraction of; MemoryKind distinguishes Reclaimable, which is real memory worth taking back but must not inflate a budget. Irq is opaque above the HAL. Timer::set_deadline is absolute, not a duration, to avoid the read/advance race. Two design.md deviations made and written back: Hal renamed Platform (stutter), and the device traits split into a sibling mlos-device crate because Console+Timer+IrqController exceeds the sw-checklist module function gate -- first time that rule bit, and the split is defensible independently. 3 tests: a null platform proving implementability and object safety (also the shape mlos-sim will need), usable_bytes excluding kernel/device/reclaimable, and page tables through the associated type.
