mlos-objtab: the ML object table. ObjectMeta carries size/precision/tier/provider/next_use/reuse_count/reload_cost/recompute_cost/share_count/mutability/owner -- each field justified by a decision it enables (three-way NextUse so Distance and Probability cannot be confused; CostNs::IMPOSSIBLE distinct from expensive so eviction can choose one and never the other; precision as a kernel choice because it is rung 2 of the degradation ladder; share_count as the basis of parameter-major scheduling). Open-addressed with linear probing rather than a tree, because the fast path is an exact match on the model-fault path. Fibonacci hashing rather than masking, with a test that fails without it: ObjectId is structured so a dense layer sweep walks consecutive ids and masking would pile a layer into adjacent slots. Removal writes a tombstone, with a test that deletes half a full table and finds the other half -- a vacancy would cut the probe chain and hide neighbours. No unsafe, no allocation, no I/O, so it is host-tested; EMPTY is a const so a kernel static can hold one. 6 tests.
