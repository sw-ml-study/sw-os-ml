Sessions are kernel objects: mlos-session (no_std, shared with the simulator) holds a record per session -- id, Contract {quality_floor, latency_ceiling_ns, resident_ceiling}, resident bytes -- in sixteen fixed slots, refusing a seventeenth. The manager charges the owner's account before choosing a victim (so an over-ceiling acquire is refused and evicts nothing) and credits on eviction; destroy_session evicts what a session owned, forgets those objects and the session, stopping if an eviction is refused. Both replays adopt the trace's sessions first and destroy them last; Outcome::sessions counts them. Shell: session | session new [KIB] | session end ID. Only resident_ceiling is enforced now; latency_ceiling_ns is for step 004, quality_floor for M5. Sessions without processes: only the shell and replay create them, get acts as session 1. M3 counts unchanged: the replay boot test passes before and after the fault-path split. sw-checklist 13 (two new, documented). Branch pr/session-objects, PR opened.
